Day 11: Modules

What are Modules?

Modules allow you to split your code into separate files, making it more organized, reusable, and maintainable. Each module has its own scope.

Benefits of Modules:

  • Code organization and maintainability
  • Reusability across different parts of the application
  • Encapsulation (private variables/functions)
  • Dependency management
  • Easier testing and debugging
  • Better performance (tree shaking, lazy loading)
ES6 Modules (ESM)

ES6 introduced a native module system for JavaScript. ES6 modules are statically analyzed, which allows for better optimization.

Basic Export/Import:

// math.js - Exporting module
export const PI = 3.14159;

export function add(a, b) {
    return a + b;
}

export function multiply(a, b) {
    return a * b;
}

// main.js - Importing module
import { PI, add, multiply } from './math.js';

console.log(PI); // 3.14159
console.log(add(2, 3)); // 5
console.log(multiply(4, 5)); // 20

Default Exports:

// calculator.js
export default class Calculator {
    add(a, b) { return a + b; }
    subtract(a, b) { return a - b; }
}

// main.js
import Calculator from './calculator.js';

const calc = new Calculator();
console.log(calc.add(5, 3)); // 8
Named vs Default Exports

You can export multiple named exports from a module, or one default export.

Named Exports:

// utils.js
export const formatDate = (date) => date.toLocaleDateString();
export const capitalize = (str) => str.charAt(0).toUpperCase() + str.slice(1);
export const generateId = () => Math.random().toString(36).substr(2, 9);

// Usage
import { formatDate, capitalize } from './utils.js';
import { generateId as idGenerator } from './utils.js'; // Aliased import

Default Exports:

// One default export per module
export default function greet(name) {
    return `Hello, ${name}!`;
}

// Or
const greet = (name) => `Hello, ${name}!`;
export default greet;

// Usage
import greet from './greetings.js';
console.log(greet('World')); // 'Hello, World!'

Mixed Exports:

// api.js
const API_BASE_URL = 'https://api.example.com';

export const getUsers = () => fetch(`${API_BASE_URL}/users`);
export const getPosts = () => fetch(`${API_BASE_URL}/posts`);

export default {
    baseURL: API_BASE_URL,
    getUsers,
    getPosts
};

// Usage
import api, { getUsers, getPosts } from './api.js';
Dynamic Imports

Dynamic imports allow you to load modules asynchronously, which is useful for code splitting and lazy loading. 

// Static import (loaded at module initialization)
import { heavyFunction } from './heavyModule.js';

// Dynamic import (loaded when needed)
async function loadHeavyModule() {
    try {
        const module = await import('./heavyModule.js');
        module.heavyFunction();
    } catch (error) {
        console.log('Failed to load module:', error);
    }
}

// Usage
document.querySelector('#loadButton').addEventListener('click', loadHeavyModule);

// Conditional loading
async function loadLocaleModule(locale) {
    const module = await import(`./locales/${locale}.js`);
    return module.translations;
}

// React-like lazy loading
const LazyComponent = React.lazy(() => import('./HeavyComponent.js'));
Module Patterns (Pre-ES6)

Before ES6 modules, JavaScript used various patterns to achieve modularity.

IIFE (Immediately Invoked Function Expression):

// Module pattern using IIFE
const Calculator = (function() {
    // Private variables
    let memory = 0;
    
    // Private function
    function validateNumber(num) {
        return typeof num === 'number' && !isNaN(num);
    }
    
    // Public API
    return {
        add: function(a, b) {
            if (validateNumber(a) && validateNumber(b)) {
                return a + b;
            }
            throw new Error('Invalid numbers');
        },
        getMemory: function() {
            return memory;
        },
        setMemory: function(value) {
            memory = value;
        }
    };
})();

// Usage
console.log(Calculator.add(5, 3)); // 8
Calculator.setMemory(42);
console.log(Calculator.getMemory()); // 42

CommonJS (Node.js):

// math.js
const PI = 3.14159;

function add(a, b) {
    return a + b;
}

module.exports = {
    PI,
    add
};

// Or
module.exports.PI = PI;
module.exports.add = add;

// main.js
const math = require('./math');
console.log(math.PI); // 3.14159
console.log(math.add(2, 3)); // 5
Module Bundlers

Module bundlers combine multiple modules into a single file for browser usage.

Webpack Configuration:

// webpack.config.js
const path = require('path');

module.exports = {
    entry: './src/index.js',
    output: {
        filename: 'bundle.js',
        path: path.resolve(__dirname, 'dist'),
    },
    module: {
        rules: [
            {
                test: /\.js$/,
                exclude: /node_modules/,
                use: {
                    loader: 'babel-loader',
                    options: {
                        presets: ['@babel/preset-env']
                    }
                }
            }
        ]
    },
    mode: 'development'
};

Popular Bundlers:

  • Webpack - Most popular, highly configurable
  • Parcel - Zero configuration bundler
  • Rollup - Optimized for libraries
  • Vite - Fast development server, uses ES modules
  • esbuild - Extremely fast, written in Go
Tree Shaking

Tree shaking is a technique to eliminate dead code from bundles, reducing file size. 

// utils.js
export const usedFunction = () => 'I am used';
export const unusedFunction = () => 'I am not used';
export const anotherUnused = () => 'Also not used';

// main.js
import { usedFunction } from './utils.js';
// Only usedFunction will be included in the bundle

// For side-effect imports, use explicit imports
import './styles.css'; // CSS is considered a side effect

// Or mark modules as having side effects in package.json
{
    "sideEffects": [
        "*.css",
        "./src/polyfills.js"
    ]
}
Module Resolution

How JavaScript resolves module imports and file paths.

Relative Imports:

// From src/components/Button.js
import { Icon } from '../icons/Icon.js';     // Go up one level
import styles from './Button.module.css';   // Same directory
import utils from '../../utils/helpers.js'; // Go up two levels

Absolute Imports:

// Configure path mapping in bundler
import { api } from '@/services/api';       // @/ maps to src/
import Button from 'components/Button';     // components/ maps to src/components/
import utils from 'utils';                  // utils/ maps to src/utils/

File Extensions:

// Usually optional in modern bundlers
import config from './config.js';    // .js extension
import styles from './styles.css';   // .css extension
import data from './data.json';      // .json extension

// TypeScript
import Component from './Component'; // .ts or .tsx inferred
Best Practices

Guidelines for organizing and using modules effectively.

Organization:

  • Group related functionality in the same module
  • Use index.js files for clean imports
  • Keep modules focused on a single responsibility
  • Use consistent naming conventions
  • Avoid circular dependencies

Import/Export Patterns:

// Barrel exports (index.js)
export { default as Button } from './Button.js';
export { default as Input } from './Input.js';
export { default as Modal } from './Modal.js';

// Usage
import { Button, Input, Modal } from './components';

// Prefer named exports for multiple exports
// Prefer default exports for single exports

// Avoid namespace imports unless necessary
// import * as Utils from './utils'; // Avoid
// import { formatDate, capitalize } from './utils'; // Prefer
