Day 12: Working with APIs

What are APIs?

APIs (Application Programming Interfaces) allow different software applications to communicate with each other. Web APIs enable your JavaScript code to interact with servers and external services.

Types of Web APIs:

  • REST APIs - Representational State Transfer
  • GraphQL APIs - Query language for APIs
  • WebSocket APIs - Real-time bidirectional communication
  • Browser APIs - Built-in browser functionality (DOM, Fetch, etc.)
Fetch API

The Fetch API provides a modern, promise-based way to make HTTP requests. It's the modern replacement for XMLHttpRequest.

Basic GET Request:

fetch('https://jsonplaceholder.typicode.com/posts/1')
    .then(response => {
        if (!response.ok) {
            throw new Error('Network response was not ok');
        }
        return response.json();
    })
    .then(data => {
        console.log('Success:', data);
    })
    .catch(error => {
        console.log('Error:', error);
    });

POST Request:

const postData = {
    title: 'My Post',
    body: 'This is the content of my post',
    userId: 1
};

fetch('https://jsonplaceholder.typicode.com/posts', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
    },
    body: JSON.stringify(postData)
})
.then(response => response.json())
.then(data => {
    console.log('Success:', data);
})
.catch(error => {
    console.log('Error:', error);
});
Async/Await with Fetch

Using async/await makes working with promises more readable and synchronous-looking. 

async function fetchPosts() {
    try {
        const response = await fetch('https://jsonplaceholder.typicode.com/posts');
        
        if (!response.ok) {
            throw new Error(`HTTP error! status: ${response.status}`);
        }
        
        const posts = await response.json();
        console.log('Posts:', posts);
        return posts;
    } catch (error) {
        console.log('Error fetching posts:', error);
        throw error; // Re-throw to allow caller to handle
    }
}

// Usage
async function displayPosts() {
    try {
        const posts = await fetchPosts();
        // Display posts in UI
        posts.forEach(post => {
            console.log(`Title: ${post.title}`);
        });
    } catch (error) {
        // Show error message to user
        console.log('Failed to load posts');
    }
}
HTTP Methods and Status Codes

Understanding HTTP methods and how to handle different response status codes.

Common HTTP Methods:

// GET - Retrieve data
const getData = () => fetch('/api/data');

// POST - Create new resource
const createData = (data) => fetch('/api/data', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data)
});

// PUT - Update entire resource
const updateData = (id, data) => fetch(`/api/data/${id}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data)
});

// PATCH - Partial update
const patchData = (id, updates) => fetch(`/api/data/${id}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(updates)
});

// DELETE - Remove resource
const deleteData = (id) => fetch(`/api/data/${id}`, {
    method: 'DELETE'
});

Status Code Handling:

async function handleApiResponse(response) {
    switch (response.status) {
        case 200:
        case 201:
            return await response.json();
        case 204:
            return null; // No content
        case 400:
            throw new Error('Bad request - check your input');
        case 401:
            throw new Error('Unauthorized - please log in');
        case 403:
            throw new Error('Forbidden - insufficient permissions');
        case 404:
            throw new Error('Resource not found');
        case 422:
            const errors = await response.json();
            throw new Error(`Validation failed: ${errors.message}`);
        case 500:
            throw new Error('Server error - please try again later');
        default:
            throw new Error(`Unexpected status: ${response.status}`);
    }
}
Headers and Authentication

HTTP headers provide metadata about the request/response. Authentication headers are crucial for secure API access.

Common Headers:

const headers = {
    'Content-Type': 'application/json',
    'Accept': 'application/json',
    'Authorization': 'Bearer your-token-here',
    'X-API-Key': 'your-api-key',
    'User-Agent': 'MyApp/1.0'
};

fetch('/api/data', {
    method: 'GET',
    headers: headers
})
.then(response => response.json())
.then(data => console.log(data));

Authentication Patterns:

// JWT Token
const token = localStorage.getItem('authToken');
const authHeaders = {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
};

// API Key
const apiHeaders = {
    'X-API-Key': 'your-api-key-here',
    'Content-Type': 'application/json'
};

// Basic Auth (not recommended for production)
const credentials = btoa('username:password');

Error Handling and Retry Logic

Robust API calls need proper error handling and retry mechanisms. 

async function fetchWithRetry(url, options = {}, maxRetries = 3) {
    let lastError;
    
    for (let attempt = 1; attempt <= maxRetries; attempt++) {
        try {
            const response = await fetch(url, options);
            
            if (response.ok) {
                return await response.json();
            }
            
            // Handle specific error codes
            if (response.status === 429) {
                // Rate limited - wait longer
                const retryAfter = response.headers.get('Retry-After') || 5;
                await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
                continue;
            }
            
            if (response.status >= 500) {
                // Server error - retry
                throw new Error(`Server error: ${response.status}`);
            }
            
            // Client error - don't retry
            throw new Error(`Client error: ${response.status}`);
            
        } catch (error) {
            lastError = error;
            
            if (attempt === maxRetries) {
                break;
            }
            
            // Exponential backoff
            const delay = Math.pow(2, attempt) * 1000;
            console.log(`Attempt ${attempt} failed, retrying in ${delay}ms...`);
            await new Promise(resolve => setTimeout(resolve, delay));
        }
    }
    
    throw lastError;
}

// Usage
try {
    const data = await fetchWithRetry('/api/data');
    console.log('Success:', data);
} catch (error) {
    console.log('All retries failed:', error.message);
}

Libraries that simplify API interactions and provide additional features.

// Interceptors for requests/responses
axios.interceptors.request.use(config => {
    // Add auth token to requests
    config.headers.Authorization = `Bearer ${getToken()}`;
    return config;
});

axios.interceptors.response.use(
    response => response,
    error => {
        if (error.response?.status === 401) {
            // Redirect to login
            window.location.href = '/login';
        }
        return Promise.reject(error);
    }
);

REST API Best Practices

Guidelines for designing and consuming REST APIs effectively.

Resource Naming:

  • Use nouns, not verbs: /users not /getUsers
  • Use plural nouns: /users not /user
  • Use lowercase and hyphens: /user-profiles
  • Nest resources logically: /users/123/posts

HTTP Status Codes:

  • 200 OK - Successful request
  • 201 Created - Resource created
  • 204 No Content - Success, no response body
  • 400 Bad Request - Invalid request
  • 401 Unauthorized - Authentication required
  • 403 Forbidden - Insufficient permissions
  • 404 Not Found - Resource doesn't exist
  • 422 Unprocessable Entity - Validation failed
  • 500 Internal Server Error - Server error
CORS and Security

Cross-Origin Resource Sharing (CORS) and security considerations when working with APIs.

CORS Headers:

// Server must include CORS headers
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true

Security Best Practices:

  • Never expose API keys in client-side code
  • Use HTTPS for all API calls
  • Validate and sanitize user input
  • Implement proper authentication and authorization
  • Use environment variables for sensitive data
  • Implement rate limiting on the server
  • Handle sensitive data appropriately (don't log passwords, tokens, etc.)
